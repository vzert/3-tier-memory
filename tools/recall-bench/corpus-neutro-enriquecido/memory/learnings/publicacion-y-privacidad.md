# Publicación y privacidad

1. **Un repo público no lleva rutas reales del usuario ni nombres de sus proyectos privados** — ni en plantillas, ni en ejemplos, ni en comentarios de código. <!-- disparadores: frases=voy a publicar el repo con ejemplos de mi sesión | la plantilla trae mi ruta real del home | estoy escribiendo un comentario con el nombre de un proyecto privado | ¿este ejemplo expone rutas reales del usuario? | voy a hacer público un repositorio nuevo | los ejemplos del README salen de mi disco real -->
2. **El escaneo de datos privados es un paso del push, no una buena intención** — va antes, porque después solo se puede borrar, no despublicar. <!-- disparadores: frases=voy a pushear a un repo público | ¿escaneo datos privados antes o después del push? | ya hice push y ahora reviso si había secretos | estoy por subir cambios sin pasar el escaneo de privacidad | me falta correr el scanner de datos privados | publiqué y después me di cuenta de que faltaba revisar; cmd=git push -->
3. **Una clave que llegó a un push público se rota** — redactarla en el historial no la des-filtra. <!-- disparadores: frases=una clave de API terminó en un push público | subí un token por error al repo | ¿basta con borrar la clave del historial? | voy a redactar la clave filtrada en los commits viejos | se filtró una credencial en GitHub | reescribí el historial pero la clave ya estuvo pública -->
4. **Un fixture de test copiado de una sesión real lleva datos del usuario** — anonimízalo antes de commitearlo. <!-- disparadores: frases=voy a copiar una sesión real como fixture de test | el fixture viene de un transcript del usuario | estoy pegando datos reales en un caso de prueba | ¿anonimizo el fixture antes de commitear? | commiteé un fixture con correos y rutas reales | creo un caso de test a partir de una conversación; cmd=git commit -->
5. **El CHANGELOG es publicación** — lo que dice sobre incidentes no nombra clientes, hosts ni cuentas. <!-- disparadores: frases=estoy escribiendo el CHANGELOG de la release | voy a describir un incidente en el changelog | ¿puedo nombrar al cliente afectado en las notas de versión? | el changelog menciona hosts y cuentas reales | redacto las notas de la release pública | agrego una entrada sobre un fallo en producción; path=CHANGELOG.md -->
6. **Los datos de medición de una instalación no se publican** — el código del banco sí; los casos, que citan sesiones, van en .gitignore. <!-- disparadores: frases=voy a subir los casos de prueba del banco al repo | los casos citan sesiones reales de mi instalación | ¿publico los datos de medición o solo el código? | estoy agregando resultados del benchmark a git | ¿van los casos en .gitignore? | quiero commitear el corpus de evaluación; cmd=git add; path=.gitignore -->
7. **Un token en una URL queda en el historial del shell y en los logs** — pásalo por variable de entorno o por fichero. <!-- disparadores: frases=voy a pasar el token en la URL del curl | pongo la clave en la URL del clone | el token quedó en el historial del shell | ¿cómo paso una credencial sin ponerla en el comando? | estoy armando una URL con la API key adentro | los logs del servidor muestran mi token; cmd=curl, git clone -->
8. **Revisa el diff saliente completo, no solo los ficheros que tocaste** — un fichero generado puede arrastrar datos. <!-- disparadores: frases=voy a revisar solo los archivos que toqué antes del push | ¿qué incluye el diff completo que se va a subir? | hay un archivo generado en el commit que no revisé | estoy por pushear y solo miré mis cambios | reviso el diff contra origin antes de publicar | un fichero generado arrastró datos al repo; cmd=git diff, git push -->
9. **Un mensaje de error puede imprimir un secreto** — no imprimas el valor de una variable de credenciales ni en modo depuración. <!-- disparadores: frases=voy a imprimir la variable de credenciales para depurar | el mensaje de error muestra la clave | estoy poniendo un echo del token en modo debug | ¿puedo loguear el valor de la variable de entorno? | el script imprime el secreto cuando falla | agrego un print para ver qué clave se usa; cmd=echo -->
10. **Las capturas de pantalla también se publican** — revisa que no muestren correos, IDs de cuenta ni rutas. <!-- disparadores: frases=voy a pegar una captura de pantalla en el issue | la captura muestra mi correo y el ID de cuenta | estoy agregando un screenshot al README | ¿la imagen deja ver rutas del sistema? | publicaré un pantallazo de la consola | subí una imagen con datos de la cuenta -->
11. **Borrar un fichero en un commit nuevo no lo borra del historial** — sigue accesible en el commit anterior. <!-- disparadores: frases=borré el archivo con secretos en un commit nuevo | ¿el fichero sigue en el historial de git? | voy a eliminar el archivo y hacer push | quité el .env del repo pero ya estaba commiteado | hice git rm y creo que ya no se ve | el archivo sigue accesible en el commit anterior; cmd=git rm -->
12. **Un issue público es publicación** — pegar un log entero en un issue puede filtrar hosts internos. <!-- disparadores: frases=voy a pegar el log completo en un issue | estoy abriendo un issue en un repo público | el log trae hosts internos y rutas | ¿puedo adjuntar la salida del error al issue? | escribo un reporte de bug con el traceback entero | comento en el issue con la salida del comando; cmd=gh issue create, gh issue comment -->
13. **La licencia va antes del primer push público** — sin ella el código no es reutilizable aunque sea visible. <!-- disparadores: frases=voy a hacer público el repo por primera vez | ¿falta el archivo LICENSE antes del primer push? | estoy preparando el lanzamiento de un proyecto open source | quiero que otros reutilicen el código | el repo es visible pero sin licencia | publico el código sin agregar licencia; cmd=git push; path=LICENSE -->
14. **Un .env de ejemplo lleva valores falsos obvios** — nunca uno real "desactivado". <!-- disparadores: frases=estoy creando un .env.example para el repo | pongo mis valores reales pero desactivados en el ejemplo | ¿qué valores van en el archivo de ejemplo de variables? | voy a copiar mi .env como plantilla | el ejemplo de entorno trae una clave comentada | agrego variables de entorno de muestra al README; path=.env.example -->
15. **Los nombres de ramas se publican con el push** — una rama con el nombre de un cliente lo expone. <!-- disparadores: frases=voy a crear una rama con el nombre del cliente | el nombre de la rama incluye un proyecto privado | ¿se publican los nombres de ramas con el push? | estoy nombrando una rama para un fix de un cliente | hice push de una rama con el nombre de la empresa | git branch con nombre de cliente; cmd=git push, git checkout -->
16. **Un commit firmado con el correo personal lo publica** — configura el correo de noreply antes de publicar. <!-- disparadores: frases=voy a hacer el primer commit en un repo público | git usa mi correo personal para el autor | ¿configuro el correo noreply antes de publicar? | el commit firmado muestra mi dirección real | estoy poniendo user.email del repo | publiqué commits con mi email personal; cmd=git commit, git config -->
17. **El borrador del CHANGELOG llevaba el nombre de un proyecto privado** — revisa el texto saliente contra la lista de proyectos antes de publicar. <!-- disparadores: frases=voy a publicar el borrador del changelog | el texto menciona un proyecto privado por nombre | ¿reviso las notas contra la lista de proyectos? | estoy por lanzar la release con el changelog redactado | el borrador de las notas nombra un cliente | reviso el texto saliente antes de publicar; path=CHANGELOG.md -->
