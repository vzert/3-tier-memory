# Git y CI

1. **Mira el CI después de cada push, no esperes al correo** — una plataforma puede quedarse en rojo varios pushes seguidos mientras cada sesión cierra diciendo "publicado". <!-- disparadores: frases=acabo de pushear, ¿ya puedo decir que quedó publicado? | el CI puede estar en rojo y no me enteré | voy a cerrar la sesión después del push sin revisar los checks | estoy esperando el correo de GitHub Actions | ¿falló el pipeline después de mi último push? | hice varios pushes y no vi el estado del workflow; cmd=git push -->
2. **Un checkout superficial no tiene la historia** — `actions/checkout` trae un solo commit por defecto; un test que lee un commit anterior con `git show` necesita `fetch-depth: 0`. <!-- disparadores: frases=el test falla en el CI al leer un commit anterior con git show | actions/checkout trae un solo commit | fatal: bad object al leer el historial en el workflow | voy a leer un commit viejo desde un test del CI | ¿necesito fetch-depth cero en el checkout? | el CI no encuentra el commit padre; cmd=git show; path=.github/workflows/* -->
3. **Nunca hagas commit en un clon mientras un revisor automático corre sobre él** — la revisión se aborta si el árbol se mueve a mitad y se pierde la ronda entera. <!-- disparadores: frases=voy a hacer commit mientras el revisor automático corre | la revisión abortó sin veredicto | estoy commiteando en el clon durante la ronda de revisión | ¿puedo seguir editando mientras corre el review? | se perdió la ronda entera porque el árbol cambió | comiteé en el clon que el adversario estaba leyendo; cmd=git commit -->
4. **Commitea antes de lanzar la revisión** — la revisión mira el HEAD, no el árbol de trabajo; lo que no está commiteado no se revisa. <!-- disparadores: frases=voy a lanzar la revisión con cambios sin commitear | el revisor no ve mis cambios recientes | ¿hace falta commit antes de pedir el review? | tengo el árbol de trabajo sucio y quiero revisar | lancé el review y no revisó lo que edité | estoy por correr el adversario sobre archivos modificados; cmd=git commit -->
5. **Sube la versión en cada push de un plugin** — el cliente usa la versión como llave de caché; misma versión significa que nadie recibe el cambio. <!-- disparadores: frases=voy a pushear un cambio del plugin sin cambiar la versión | nadie recibe mi actualización del plugin | el cliente no descarga la nueva versión del plugin | ¿subo la versión antes del push de un plugin? | publiqué un fix y los usuarios siguen con el viejo | la caché del marketplace conserva la versión anterior; cmd=git push -->
6. **Un fichero ignorado por .gitignore puede seguir trackeado** — se publica en cada push; compruébalo con `git ls-files | git check-ignore --no-index --stdin`. <!-- disparadores: frases=agregué el archivo a .gitignore pero sigue apareciendo en el push | ¿este fichero ignorado se publica igual? | voy a comprobar qué ficheros trackeados deberían estar ignorados | el gitignore no funciona para un archivo que ya estaba en el repo | estoy revisando qué se sube antes de hacer push | git sigue mostrando cambios de un archivo ignorado; cmd=git ls-files, git check-ignore; path=.gitignore -->
7. **`git config` dentro de un worktree escribe el config compartido del repo** — cambia la identidad de todos los que usan ese repo, no solo la del worktree. <!-- disparadores: frases=voy a cambiar el user.email dentro de un worktree | git config en el worktree cambió la identidad de todos | quiero otra identidad de git solo para este worktree | configuré el nombre en el worktree y afectó al repo principal | estoy poniendo el autor de commits en una carpeta worktree | ¿git config local en un worktree es solo local?; cmd=git config -->
8. **Un hash no puede contener su propio hash** — grabar el hash de un commit y amendear para incluirlo produce otro hash; se graba como referencia hacia adelante. <!-- disparadores: frases=quiero escribir el hash del commit dentro del mismo commit | voy a hacer amend para incluir el hash en el mensaje | el hash cambió después de amendear | grabo el SHA del commit en un archivo y lo commiteo | ¿cómo referencio el commit actual dentro de sí mismo? | estoy poniendo la referencia al commit en el changelog; cmd=git commit -->
9. **Rebase interactivo no funciona sin terminal** — en un agente, usa rebase no interactivo o commits nuevos. <!-- disparadores: frases=voy a hacer un rebase interactivo para aplastar commits | git rebase se cuelga esperando un editor | quiero reordenar commits con squash | el rebase abre vim y el agente no puede seguir | estoy intentando limpiar el historial de la rama | ¿cómo hago fixup de commits sin terminal?; cmd=git rebase -->
10. **Un force-push a main borra trabajo de otros** — antes de reescribir historia compartida, pregunta. <!-- disparadores: frases=voy a hacer force push a main | el push fue rechazado y quiero forzarlo | estoy por reescribir la historia de una rama compartida | git dice non-fast-forward y pienso sobrescribir el remoto | hice force-push y desaparecieron commits de otros | ¿reseteo main y lo subo a la fuerza?; cmd=git push -->
11. **El mensaje de commit de otra cuenta queda para siempre** — un fichero temporal de mensaje reutilizado mete el texto de otra sesión en el historial. <!-- disparadores: frases=voy a reutilizar el archivo temporal del mensaje de commit | el commit salió con el texto de otra sesión | usé un fichero tmp para el mensaje y estaba viejo | estoy escribiendo el mensaje de git commit desde un temporal | apareció un mensaje que yo no escribí en el historial | otra cuenta dejó un archivo de mensaje en tmp; cmd=git commit -->
12. **Windows en el CI hace checkout con CRLF** — un `case` exacto sobre texto leído conserva el `\r` final donde un `grep` de subcadena no fallaba. <!-- disparadores: frases=el test pasa en Linux y falla en Windows del CI | un case exacto no casa con el texto leído en Windows | aparece un carácter de retorno de carro al final | el checkout de Windows convierte los saltos de línea | estoy comparando una línea leída con un case en bash | el grep de subcadena sí pasa pero el case no; path=.github/workflows/* -->
13. **Una rama de medición en el CI se borra después** — sirve para medir otra plataforma sin tener la máquina. <!-- disparadores: frases=no tengo una máquina Windows para medir esto | quiero medir el comportamiento en otra plataforma usando el CI | voy a crear una rama temporal solo para medir en el CI | ¿borro la rama de medición después? | estoy usando GitHub Actions para probar en macOS | dejé una rama de prueba del workflow sin borrar; cmd=git push; path=.github/workflows/* -->
14. **Los tags de versión se crean después del merge, no antes** — un tag sobre un commit que no llegó a main apunta a nada publicado. <!-- disparadores: frases=voy a crear el tag de versión antes del merge | estoy por etiquetar la release en la rama del PR | ¿hago git tag antes o después de unir a main? | el tag apunta a un commit que no llegó a main | publiqué un tag de la versión y el PR sigue abierto | estoy tageando la versión nueva; cmd=git tag -->
15. **Un required check rojo bloquea el merge de todos** — arreglarlo va antes que cualquier otra tarea del repo. <!-- disparadores: frases=el required check está rojo y no puedo hacer merge | el PR no se une porque falla un check obligatorio | ¿sigo con otra tarea mientras el CI está en rojo? | hay un check requerido fallando en main | nadie puede mergear porque el CI está roto | voy a ignorar el check rojo y seguir con lo mío; cmd=gh pr merge -->
16. **`git stash` no guarda los ficheros sin trackear por defecto** — usa `-u` o se pierden al cambiar de rama. <!-- disparadores: frases=voy a hacer git stash antes de cambiar de rama | guardé con stash y desaparecieron mis archivos nuevos | tengo ficheros sin trackear y quiero guardarlos temporalmente | al cambiar de rama perdí archivos que no estaban en git | estoy haciendo stash de mi trabajo en progreso | ¿stash incluye los archivos untracked?; cmd=git stash -->
17. **No comitear en el clon con la revisión corriendo: la ronda aborta sin veredicto** — el árbol movido invalida la revisión; espera a que termine. <!-- disparadores: frases=la revisión corre en el clon y quiero commitear | ¿puedo comitear mientras la ronda de revisión sigue? | la ronda abortó sin veredicto después de mi commit | estoy a punto de hacer commit en el clon que revisan | el árbol se movió durante la revisión | ¿espero a que termine el revisor para commitear?; cmd=git commit -->
